รันแอป Windows ที่วันใดก็ได้ โดยไม่แตะนาฬิกาของระบบ

ตั้งนาฬิกาของแอปเพียงตัวเดียวให้เป็นปีหน้า หยุดมันไว้ หรือเร่งให้ช่วงทดลองใช้ 30 วันหมดลงระหว่างที่คุณชงกาแฟ ส่วนเครื่องที่เหลือยังใช้เวลาจริงตามเดิม - การล็อกอินโดเมน ใบรับรอง และโปรแกรมอื่นทุกตัวทำงานต่อไปตามปกติ

จากนั้นมันจะบอกคุณว่าการแทนที่เวลาได้ผลจริงหรือไม่

ทำไมถึงมีสิ่งนี้

การทดสอบทุกอย่างที่ขึ้นกับวันที่ต้องเลื่อนเวลา และสองวิธีที่ใช้กันทั่วไปล้วนไม่ดี

ไลเซนส์หมดอายุ ช่วงทดลองใช้ การต่ออายุการสมัครสมาชิก อายุของใบรับรอง อายุของโทเค็น รายงานสิ้นเดือนและสิ้นปี การคิดดอกเบี้ย การแจ้งเตือน

ทางเลือกที่ 1 - เปลี่ยนนาฬิกาของระบบ

มันทำให้การล็อกอินโดเมนและ Kerberos พัง ทำให้ใบรับรอง TLS ใช้ไม่ได้จนเบราว์เซอร์หยุดทำงาน ทำให้ Windows Update สับสน และทำให้แอปอื่นทุกตัวในเครื่องบันทึกเวลาผิด ในเครื่องที่เข้าร่วมโดเมน นโยบายกลุ่มมักบล็อกการเปลี่ยนแปลงนี้หรือเปลี่ยนกลับหลังไม่กี่นาที การทดสอบจึงทำซ้ำไม่ได้ด้วยซ้ำ

ทางเลือกที่ 2 - รอ

ซึ่งก็คือไม่ทดสอบ กรณีที่ขึ้นกับวันที่จึงถูกข้ามไป และเวอร์ชันที่ “ไลเซนส์ไม่เคยหมดอายุ” ก็ไปถึงมือลูกค้า

ทำอะไรได้บ้าง

หนึ่งโพรเซสเดินทางข้ามเวลา ส่วนทุกอย่างที่เหลือในเครื่องอยู่กับที่

ช่วงเวลาใดก็ได้

วันที่และเวลาที่เจาะจง หรือเวลาแบบสัมพัทธ์ - +30 days, -1 year

เดินปกติ หยุดนิ่ง หรือเร่งความเร็ว

ความเร็วปกติ นาฬิกาที่หยุดค้างไว้ หรือตัวคูณที่เป็นจำนวนเต็ม x1440 ทำให้หนึ่งวันเหลือหนึ่งนาที

เขตเวลาของตัวเอง

ออฟเซ็ตคงที่เฉพาะโพรเซสนั้น ขณะที่เขตเวลาของระบบอยู่ที่เดิมทุกประการ

โพรเซสย่อยไปด้วยกัน

ตัวติดตั้งและตัวเปิดแอปมักสร้างโพรเซสย่อย ถ้าไม่ตามไปด้วย การทดสอบก็ครอบคลุมแค่ครึ่งหนึ่งของสิ่งที่รัน

กระโดดกลางเซสชัน

ไปข้างหน้าหรือถอยหลังก็ได้ - รวมถึงการถอยหลังที่โน้ตบุ๊กทำหลังซิงก์กับเซิร์ฟเวอร์เวลาอีกครั้ง

Electron และ Chromium ก็ได้

ผ่านกลไกอีกแบบหนึ่ง เพราะนาฬิกาของมันอยู่ในเรนเดอเรอร์แบบแซนด์บ็อกซ์ที่การฉีดเข้าไปไม่ถึง

ส่วนที่ไม่มีใครทำ

คุณจะรู้ได้อย่างไรว่าได้ผล?

กับเครื่องมืออื่นทุกตัว คุณไม่มีทางรู้ แอปเริ่มทำงาน แสดงวันที่บางอย่าง แล้วคุณก็สันนิษฐานเอาเอง แต่แอปอาจอ่านนาฬิกาผ่านช่องทางที่เครื่องมือไม่เคยดักไว้ - จากเซิร์ฟเวอร์ จากฐานข้อมูล ผ่านเลเยอร์รันไทม์ - และเมื่อนั้นคำว่า “ทดสอบผ่าน” ก็ไม่มีความหมายเลย

  • →ผลสรุปก่อนที่การทดสอบจริงจะเริ่ม: ใช้งานได้ / ใช้งานได้บางส่วน / ใช้งานไม่ได้
  • →ช่องทางเวลา {{channel_count}} ช่องทางช่องใดบ้างที่ครอบคลุม และแอปสอบถามแต่ละช่องกี่ครั้ง
  • →ช่องทางใดที่ไม่ครอบคลุม - ระบุตรง ๆ ไม่เคยละไว้
  • →คำเตือนที่ระบุผลที่ตามมา: “แอปนี้อ่านเวลาจากเครือข่าย - การแทนที่ในเครื่องอาจไม่เพียงพอ”

สองนาทีกับมัน

หน้าต่างสำหรับสำรวจ บรรทัดคำสั่งสำหรับ CI เครื่องยนต์ตัวเดียวกันอยู่เบื้องหลังทั้งสองอย่าง

# รันแอปเสมือนว่าเป็นวินาทีสุดท้ายของปี 2027
chrono run "C:\apps\test.exe" --at 2027-12-31T23:59:59

# ดูช่วงทดลองใช้ 30 วันหมดลงระหว่างชงกาแฟ: x1440 คือหนึ่งวันต่อนาที
chrono run "C:\apps\test.exe" --mode x1440

# ใช้สถานการณ์ที่ตั้งชื่อไว้แทนวันที่ และเขียนหลักฐานลงไฟล์
chrono run "C:\apps\test.exe" --preset year-rollover --report session.txt
