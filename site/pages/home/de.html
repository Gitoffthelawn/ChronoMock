Windows-App mit beliebigem Datum ausführen - ohne die Systemuhr anzutasten

Stellen Sie die Uhr einer einzelnen Anwendung auf nächstes Jahr, frieren Sie sie ein oder beschleunigen Sie sie, sodass eine 30-Tage-Testversion abläuft, während Sie sich einen Kaffee holen. Der Rest des Rechners behält die echte Zeit - Domänenanmeldung, Zertifikate und alle anderen Programme laufen unverändert weiter.

Danach sagt es Ihnen, ob die Ersetzung tatsächlich gewirkt hat.

Warum es das gibt

Wer datumsabhängige Funktionen testet, muss die Zeit verschieben. Beide üblichen Wege taugen nichts.

Lizenzablauf, Testzeiträume, Abo-Verlängerungen, Zertifikatsgültigkeit, Token-Laufzeiten, Monats- und Jahresabschlüsse, Zinsberechnung, Erinnerungen.

Weg 1 - die Systemuhr umstellen

Das stört die Domänenanmeldung und Kerberos, macht TLS-Zertifikate ungültig, sodass der Browser nicht mehr funktioniert, verwirrt Windows Update und lässt jede andere Anwendung auf dem Rechner falsche Zeitstempel schreiben. Auf einem Rechner in einer Domäne blockiert die Gruppenrichtlinie die Änderung meist oder macht sie nach Minuten rückgängig - der Test ist also nicht einmal wiederholbar.

Weg 2 - abwarten

Das heißt: nicht testen. Die datumsabhängigen Fälle fallen unter den Tisch, und „die Lizenz läuft nie ab“ geht an den Kunden.

Was es kann

Ein einziger Prozess bewegt sich durch die Zeit. Alles andere auf dem Rechner nicht.

Jeder Zeitpunkt

Ein bestimmtes Datum mit Uhrzeit oder ein relativer Wert - +30 days, -1 year.

Laufend, eingefroren oder beschleunigt

Normale Geschwindigkeit, eine angehaltene Uhr oder ein ganzzahliger Faktor. x1440 macht aus einem Tag eine Minute.

Eine eigene Zeitzone

Ein fester Offset nur für diesen Prozess, während die Systemzone genau dort bleibt, wo sie war.

Kindprozesse kommen mit

Installer und Launcher starten Kindprozesse. Ohne sie deckt der Test nur die Hälfte dessen ab, was lief.

Sprünge mitten in der Sitzung

Vorwärts oder rückwärts - auch der Rückwärtssprung, den ein Laptop nach dem Abgleich mit einem Zeitserver macht.

Auch Electron und Chromium

Über einen anderen Mechanismus, denn ihre Uhr liegt in einem abgeschotteten Renderer, den Injektion nicht erreicht.

Das, was sonst niemand macht

Woher wissen Sie, dass es gewirkt hat?

Bei jedem anderen Werkzeug wissen Sie es nicht. Die Anwendung startet, zeigt irgendein Datum, und Sie nehmen an, dass es stimmt. Sie kann die Uhr aber über einen Kanal lesen, den das Werkzeug nie abgefangen hat - von einem Server, aus einer Datenbank, über eine Laufzeitschicht - und dann bedeutet „der Test ist bestanden“ gar nichts.

  • →Warnungen mit Folgen: „Diese Anwendung liest die Zeit aus dem Netzwerk - lokale Ersetzung reicht möglicherweise nicht aus“

Zwei Minuten damit

Ein Fenster zum Ausprobieren, eine Kommandozeile für die CI. Dahinter dieselbe Engine.

# Eine Anwendung so ausführen, als wäre es die letzte Sekunde des Jahres 2027
chrono run "C:\apps\test.exe" --at 2027-12-31T23:59:59

# Zusehen, wie eine 30-Tage-Testversion abläuft, während Sie Kaffee holen: x1440 ist ein Tag pro Minute
chrono run "C:\apps\test.exe" --mode x1440

# Ein benanntes Szenario statt eines Datums verwenden und den Nachweis in eine Datei schreiben
chrono run "C:\apps\test.exe" --preset year-rollover --report session.txt
